**BẪY LỚN PHÁT HIỆN GIỮA CHỪNG — namespace ambiguity `Cell` (đáng nhớ cho lần refactor tương tự sau này):**
`World/Cell.cs` (world map, struct đã có từ Phase 1+2 ở trên) và `LocalMap/Grid/Cell.cs` (mới) CÙNG TÊN `Cell` khác namespace. C# resolve tên kiểu ưu tiên **namespace bao ngoài (enclosing) TRƯỚC `using` directive** — nghĩa là bất kỳ file nào nằm trong `Nizhangjie.World.*` (vd `Nizhangjie.World.Wild.Zones`, `Nizhangjie.World.Wild.UI`) viết TƯỜNG MINH kiểu `Cell` (không qua `var`) sẽ tự động resolve về `Nizhangjie.World.Cell` — **DÙ file đó có `using Nizhangjie.LocalMap.Grid;`** — không ambiguous, không lỗi compile, nhưng SAI KIỂU NGẦM (chỉ lộ ra nếu code sau đó dùng field không tồn tại trên World.Cell, như `.Type` → mới báo lỗi CS1061). Đã bắt được 3 chỗ dính: `WildZoneOps.IsFishableWater(Cell? tile)`, `WildSceneInteraction.PlaceStorage(Cell? tileOpt)` + call site `as Cell?` — phải fully-qualify `Nizhangjie.LocalMap.Grid.Cell` tường minh. Ngược lại, file KHÔNG nằm trong `Nizhangjie.World.*` (vd `Nizhangjie.Tests.Editor`) mà có CẢ 2 using (`using Nizhangjie.World;` + `using Nizhangjie.LocalMap.Grid;`) thì `Cell` trần mới thật sự AMBIGUOUS (CS0104) — gặp ở `M12LocalGenTest.cs` (5 chỗ, đã fix bằng qualify `World.Cell` vì đó đúng là world-tile input cho generator). **Quy tắc rút ra: mọi kiểu tên trùng giữa `Nizhangjie.World` và `Nizhangjie.LocalMap.Grid` PHẢI fully-qualify tường minh khi viết type name rõ ràng (param/return/field), `var`/type-inference thì an toàn (bind theo method signature thật, không qua name lookup).**
